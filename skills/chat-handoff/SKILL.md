# Chat Handoff

English: Save original AI conversations locally and maintain an index so another session or agent can continue. Run only when the user requests export, append, or organization; do not collect or upload chats automatically.

## 交付与边界

只有用户明确触发导出、追加或整理时才执行。默认当前窗口；其他窗口、历史或全盘整理需要相应授权。不安装后台任务、监听器或自动采集，不因模型切换自动导出。

目的：将用户选择留存的交互历史保存为本地资产，让另一个 Agent 通过原话、讨论过程和交接日志继续工作，而不是只依赖重写的交接报告。

- 聊天原文是交接材料；梗概只帮助定位，不替代原话、项目真源或当前待办。
- 没有固定 Agent 数量、品牌、业务主题、前缀或阶段模板。
- 首次确定用户选定的工作区与位置，遵循当地规则，不推断其目录结构或存储服务。
- 本 Skill 默认 `chat-history/`，元数据默认 `.chat-handoff/`。可通过 `CHAT_HANDOFF_ARCHIVE`、`CHAT_HANDOFF_METADATA` 设置相对路径；所有提交者使用同一配置。不擅自迁移既有交接区。
- 对话、注册表、事务、暂存稿及个人安装配置均为本地数据，不属于公开 Skill 或代码仓库。

## 不变量与判断空间

必须保护原文字节、完整来源、消息顺序、实际日期、追溯关系和功能引用。日常追加只在末尾新增；授权重排时完整旧入口永久保存，不能只放到未来会清理的备份里。

Agent 判断语义，不按关键词、文件大小、窗口、功能数量或模型品牌自动分类：

1. 同目标、同采用路线、同阶段的连续推进通常保持一条历史；多个功能不自动拆档。
2. 有独立交付／办理过程的配套工作、尚未采用的替代尝试，可以作为相关专项。
3. 阶段看路线、交付形态或运行状态的实质变化，不按日期或篇幅硬分。
4. 具体专项优先归其直接服务的项目；引用宏观目标不自动提升成上层主线。
5. 主目标不同可建新前缀，登记关系，不强套现有名称；短期事件不强套阶段。

已有明确范围直接续接。实质新目标、主线／专项或阶段边界，先多读相关原文，再用人话说明建议，只问一个必要的确认问题。用户已明确批准的本轮计划算授权，不把它延用于未来任意新结构。分类允许事后纠正，原文不改。

## 每次先读

1. 用户选定工作区的规则及已有资料索引；没有某个固定文件名也能使用，不自动创建私人工作系统。
2. 交接区 `README.md` 的速查表，候选目标的梗概、适合追加／不混入、关系与历史。
3. 候选原文和相关业务真源。不能仅据日志认定当前业务已完成。
4. 注册表原字节和 SHA-256。旧路径找不到先解析 ID／旧名，多个匹配逐一判断，不选第一个。

初始化仅用于用户认可的新位置：

```bash
python <skill>/scripts/topic_archive.py <workspace> init
```

已有资料先清点审阅，不覆盖初始化。后续命令在工作区根执行，以实际安装路径替换 `<skill>`，不要求 Skill 装在某种客户端的固定目录。

## 取源与阅读

按会话 ID 和至少两条独特可见原话核对，不凭最新文件或 mtime。读取器见 [取源说明](references/native-export.md)。原生记录只读，只新建唯一暂存 Markdown；不支持的格式先验证适配，不假称已经支持。

完整阅读本次用户发言及对应回复，再决定归属。默认保留可见文字，不导出隐藏思考，工具另按明确要求处理。标明真实模型；未知记未知。附件缺口明示，不把文字稿称为完整运行日志。

完整问答是默认单元。只有独立段落能无损分清时才分段，保留双方、否定、转折与条件；否则完整单元归主主题，其他入口交叉关联。完整混合原稿永久保存。

累积导出先核对已归档范围。相同旧问答通过 `already_archived` 精确指向原来源区间；跨格式需核对原生消息 ID、时间和正文，再导出干净增量。不自动模糊去重，不把「重复提问但回答不同」删掉。

## 命名与日志

建议 `YYYY-MM-DD_<项目前缀>-<连续阶段／专项／事件标题>_original.md`。

- 同目标沿用已登记前缀的精确文字；真正新目标可确认新名称。
- 日期是本入口覆盖的最后实际会话日期，按统一时区；不是整理日、导出日、文件时间或计划日。无法核实先查证。
- 较早补录仍只追加，在日志记原时间，不假装物理顺序等于时间顺序。
- 稳定 ID 不随日期、显示名或 Agent 变化；保留旧名映射。旧 H1 属于历史，不改字来匹配新文件名。
- 注册表是机器真源，生成唯一的人读 README；不要另造独立手写总日志。
- 每入口维护目标、梗概、适合续接、不混入、关联、原文依据与来源历史。提交时间和实际会话日期分开；未知作者／首次导出时间不补猜。

## 统一提交

```bash
python <skill>/scripts/topic_archive.py . resolve "<旧名或ID>"
python <skill>/scripts/topic_archive.py . inspect-file "chat-history/incoming/<唯一标识>.md" --output ".chat-handoff/<标识>-inspection.json"
python <skill>/scripts/topic_archive.py . route ".chat-handoff/<标识>-plan.json"
python <skill>/scripts/topic_archive.py . route ".chat-handoff/<标识>-plan.json" --apply
python <skill>/scripts/topic_archive.py . verify
```

以上为默认路径示例；有自定义目录时全部使用已确认配置。计划字段及高级维护见 [提交协议](references/submission.md)。

提交前填写注册表版本哈希、实际提交者、会话 ID／提交游标（有证据时）、每目标当前哈希、消息范围、日期及承接决定。身份字段开放，不猜历史作者。梗概无变化可沿用。

短锁只覆盖核验及提交，不覆盖模型思考。版本变化须重读当前日志、目标和候选增量，重新判断剩余消息，不能只刷新哈希强行写入。聊天、注册表、日志、路径迁移及历史事件通过同一可恢复事务提交。

中断时先恢复，第三种内容停止，不覆盖后来写入：

```bash
python <skill>/scripts/topic_archive.py . recover
python <skill>/scripts/topic_archive.py . verify
```

不删除锁文件抢锁；未完成事务证据不得清理。本机锁不覆盖多个机器的独立副本，跨机约定一个提交方；真正同时写入需要另外的共享事务服务。

## 整理与引用安全

全盘整理须获授权并逐份阅读，不以标题扫描或哈希检查冒充通读。不为「整理过」而改名，不硬合并不同目标。

- 只改元数据、纯更名或完整补登记，用 `archive_catalog.py`；拆合原区间用 `regroup_archive.py`，先预检再提交。
- 重排前永久保存完整旧入口，核对每个区间及重复出现次数，不能删重、改写或用摘要替代。
- 改名／移走前扫描工作区的代码、配置及 Markdown／JSON／CSV／JSONL 等索引。每个命中明确迁移还是历史证据；冻结哈希和行号继续指原证据，不改写成新哈希。
- 外部系统的来源身份不随主题入口更名变化；不重复导入派生视图。
- 暂存稿只有证明消息完整纳入或明确登记缺口后才退役。移入可恢复垃圾桶并登记，不自动永久删除；永久来源不依赖垃圾桶期限。

## 验收与交付

校验来源与区间 SHA-256、旧前缀／纯更名字节、实际日期、ID／别名、日志同步、路径依赖及未登记入口。字节完整与语义归属分开验收。

用简短语言报告当前追加位置、覆盖时间、缺口、冲突和接手入口。只验证本机就只说本机，不把归档成功说成业务完成。公开分享或上传原文需另获授权；仓库中的 Skill 不含用户聊天和私人配置。
